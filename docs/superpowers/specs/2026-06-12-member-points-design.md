# Member Points and Tier System Design

## เป้าหมาย

เพิ่มระบบสะสมแต้มให้สมาชิก TNC Garment โดยใช้ยอดชำระจริงในอัตรา
`1 บาท = 1 แต้ม` สมาชิกใช้แต้มเพื่อดูยอดสะสมและระดับสมาชิกเท่านั้น
ยังไม่รองรับการแลกแต้ม ส่วนลดจากแต้ม หรือวันหมดอายุของแต้ม

ระบบต้องให้แอดมินบันทึกและยกเลิกออร์เดอร์ผ่านหน้าหลังบ้าน สมาชิกเห็นแต้ม
Tier สิทธิประโยชน์ และประวัติออร์เดอร์หลังล็อกอิน โดยใช้ Google Sheets
และ Google Apps Script ตามสถาปัตยกรรมเดิม

## กติกาธุรกิจ

### การสะสมแต้ม

- ออร์เดอร์ที่บันทึกสำเร็จมีสถานะ `ACTIVE`
- แต้มที่ได้รับเท่ากับยอดชำระของออร์เดอร์ โดยรองรับทศนิยมสูงสุด 2 ตำแหน่ง
- ยอดต้องมากกว่า `0` และไม่เกิน `10,000,000` บาทต่อออร์เดอร์
- แต้มสะสมไม่มีวันหมดอายุ
- สมาชิกไม่สามารถโอน ใช้ หรือแลกแต้มได้
- แต้มคงเหลือคำนวณจากผลรวมออร์เดอร์สถานะ `ACTIVE` เท่านั้น

### Tier

| Tier | แต้มขั้นต่ำ | สิทธิประโยชน์ |
|---|---:|---|
| Silver | 0 | ส่วนลด 5% |
| Gold | 30,000 | ส่วนลด 8%, ลำดับผลิตก่อน, ออกแบบฟรี 1 ครั้ง/ออร์เดอร์, ตัวอย่างฟรี 1 ชิ้น/ออร์เดอร์ |
| Platinum | 100,000 | ส่วนลด 12%, ลำดับผลิตก่อน, ออกแบบฟรี, ตัวอย่างและจัดส่งฟรี, ล็อกราคา 6 เดือน, แอดมินดูแลเฉพาะ, เชิญร่วมกิจกรรม |

- ระบบคำนวณ Tier ทันทีหลังเพิ่มหรือยกเลิกออร์เดอร์
- เมื่อยกเลิกออร์เดอร์และแต้มลดต่ำกว่าเกณฑ์ Tier ต้องลดลงตามแต้มใหม่
- สมาชิกที่ยังไม่มีออร์เดอร์เริ่มต้นที่ `0` แต้มและ Tier `Silver`

### การยกเลิกออร์เดอร์

- ห้ามแก้ไขยอด ลบแถว หรือเปลี่ยนสมาชิกของออร์เดอร์เดิม
- แอดมินยกเลิกออร์เดอร์ได้ครั้งเดียวและต้องระบุเหตุผล 3-300 ตัวอักษร
- ออร์เดอร์ที่ยกเลิกเปลี่ยนสถานะเป็น `CANCELLED`
- เก็บเวลา ผู้ยกเลิก และเหตุผลไว้ในออร์เดอร์
- การยกเลิกต้องหักแต้มและคำนวณ Tier ใหม่ภายใน critical section
  ที่ครอบด้วย `ScriptLock` เดียวกัน
- ห้ามยกเลิกออร์เดอร์ที่ถูกยกเลิกแล้ว

## โครงสร้างข้อมูล

### Members

เพิ่มคอลัมน์ท้าย schema เดิมเพื่อให้ migration ไม่กระทบข้อมูล:

| Field | Type | ค่าเริ่มต้น | รายละเอียด |
|---|---|---:|---|
| points | Number | 0 | ผลรวมยอดออร์เดอร์ ACTIVE |
| tier | String | Silver | Silver, Gold หรือ Platinum |
| lastOrderAt | ISO Date String | ว่าง | วันที่ออร์เดอร์ ACTIVE ล่าสุด |

ฟิลด์ทั้งสามเป็นค่าที่ระบบดูแล แอดมินและสมาชิกแก้ไขโดยตรงไม่ได้
การเก็บค่ารวมใน `Members` ช่วยให้หน้ารายการสมาชิกและหน้า Member Portal
ไม่ต้องสแกนชีต `Orders` ทุกครั้ง

### Orders

สร้างชีต `Orders` พร้อมคอลัมน์:

| Field | Type | รายละเอียด |
|---|---|---|
| orderId | String | รูปแบบ `ORD-000001` |
| memberId | String | อ้างอิงสมาชิกที่มีอยู่ |
| memberName | String | snapshot ชื่อ ณ เวลาบันทึก |
| orderDate | ISO Date String | วันที่รับชำระที่แอดมินเลือก |
| amount | Number | ยอดชำระและแต้มที่ได้รับ |
| note | String | หมายเหตุ ไม่บังคับ สูงสุด 500 ตัวอักษร |
| status | String | `ACTIVE` หรือ `CANCELLED` |
| createdAt | ISO Date String | เวลาบันทึก |
| createdBy | String | อีเมลแอดมิน |
| cancelledAt | ISO Date String | เวลายกเลิก |
| cancelledBy | String | อีเมลแอดมินผู้ยกเลิก |
| cancellationReason | String | เหตุผลการยกเลิก |

### Settings

เพิ่มค่า `LAST_ORDER_SEQUENCE` สำหรับออกเลขออร์เดอร์ต่อเนื่อง การอ่านและเพิ่มค่า
ต้องอยู่ภายใน `LockService` เดียวกับการสร้างออร์เดอร์

### AuditLog

เพิ่ม action:

- `ORDER_CREATE` บันทึกข้อมูลออร์เดอร์ที่สร้าง
- `ORDER_CANCEL` บันทึกสถานะก่อนและหลัง เหตุผล และผลรวมแต้ม/Tier ใหม่
- `POINTS_REBUILD` บันทึกผลการซ่อมยอดกรณีแอดมินสั่ง rebuild

ห้ามบันทึก PIN, hash, salt หรือ session token ใน AuditLog

## สถาปัตยกรรม

### Points Core

สร้างโมดูล pure functions สำหรับ:

- ตรวจและ normalize payload ออร์เดอร์
- คำนวณแต้มจากยอดชำระ
- คำนวณ Tier จากแต้ม
- คืนรายการสิทธิประโยชน์ตาม Tier
- คำนวณ summary จากรายการออร์เดอร์ ACTIVE

โมดูลนี้ไม่มี dependency กับ Apps Script เพื่อทดสอบด้วย Node.js ได้โดยตรง

### Order Service

รับผิดชอบกติกาธุรกิจ:

- `createOrder(payload, actor)`
- `cancelOrder(payload, actor)`
- `listMemberOrders(memberId, query)`
- `rebuildMemberPoints(memberId, actor)`

การสร้างและยกเลิกใช้ `repository.withLock()` ครอบการตรวจสมาชิก ออกเลขออร์เดอร์
บันทึกออร์เดอร์ อัปเดต summary สมาชิก และ AuditLog เพื่อป้องกันข้อมูลครึ่งชุด

### Sheet Repository

เพิ่ม repository สำหรับ `Orders` ที่อ่านแบบ batch และเขียนเฉพาะแถวเป้าหมาย:

- ค้นออร์เดอร์ด้วย `orderId`
- เพิ่มออร์เดอร์
- เปลี่ยนสถานะเป็นยกเลิก
- แสดงออร์เดอร์ของสมาชิกแบบกรองและแบ่งหน้า
- รวม summary ของสมาชิกเพื่อใช้ตรวจสอบหรือ rebuild

การเปิดหน้าสมาชิกอ่าน summary จาก `Members` ก่อน และอ่าน `Orders` เฉพาะเมื่อขอ
หน้าประวัติ ช่วยลดจำนวน cell ที่อ่านในคำขอทั่วไป

## API

### Admin

- `createOrder(payload)` รับ `memberId`, `orderDate`, `amount`, `note`
- `cancelOrder(payload)` รับ `orderId`, `reason`
- `listMemberOrders(query)` รับ `memberId`, `status`, `page`, `pageSize`
- `rebuildMemberPoints(memberId)` ใช้ซ่อม summary จาก Orders เมื่อจำเป็น

ทุก API ต้องผ่าน `withAdmin()` และคืน error code คงที่:

- `VALIDATION_ERROR`
- `UNAUTHORIZED`
- `NOT_FOUND`
- `ORDER_ALREADY_CANCELLED`
- `MEMBER_SUSPENDED`
- `SYSTEM_ERROR`

ระบบไม่อนุญาตให้เพิ่มออร์เดอร์ให้สมาชิกสถานะ `ระงับ`

### Member

- ขยาย `getMemberAccount(token)` ให้คืน `points`, `tier`, `benefits`,
  `lastOrderAt` พร้อมข้อมูลเดิม
- เพิ่ม `getMyOrders(payload)` รับ `token`, `page`, `pageSize`
- สมาชิกเห็นเฉพาะออร์เดอร์ของ memberId ใน session token
- ประวัติแสดงทั้ง ACTIVE และ CANCELLED เพื่อความโปร่งใส

ข้อมูลที่ส่งให้ client ต้องผ่าน safe mapper และไม่รวมข้อมูล auth ภายใน

## หน้าหลังบ้าน

ภายในหน้ารายละเอียดสมาชิก เพิ่มส่วน `แต้มและออร์เดอร์`:

- การ์ดแสดงแต้มปัจจุบัน Tier และวันที่สั่งซื้อล่าสุด
- ฟอร์มเพิ่มออร์เดอร์: วันที่, ยอดชำระ, หมายเหตุ
- ตารางประวัติ: เลขออร์เดอร์, วันที่, ยอด/แต้ม, สถานะ, ผู้บันทึก
- ปุ่มยกเลิกแสดงเฉพาะรายการ ACTIVE
- dialog ยืนยันการยกเลิกและบังคับกรอกเหตุผล
- หลังเพิ่มหรือยกเลิก อัปเดต summary และตารางโดยไม่ reload ทั้งหน้า

ต้องปิดปุ่มระหว่างส่งคำขอ ป้องกันการกดซ้ำ และสร้าง DOM ด้วย `textContent`
โดยไม่ใช้ `innerHTML` กับข้อมูลผู้ใช้

## Member Portal

หลังล็อกอิน เพิ่ม:

- การ์ดแต้มขนาดเด่น
- badge Tier
- รายการสิทธิประโยชน์ตาม Tier
- แถบความคืบหน้าไป Tier ถัดไป โดย Platinum แสดงว่าเป็นระดับสูงสุด
- วันที่สั่งซื้อล่าสุด
- ตารางประวัติออร์เดอร์แบบแบ่งหน้า หน้าละ 10 รายการ
- รายการยกเลิกแสดงสถานะชัดเจนและไม่นับในแต้ม

หน้าแต้มต้องยังใช้งานด้วย keyboard และ screen reader ได้ รวมทั้ง responsive
บนโทรศัพท์โดยไม่ต้องเพิ่ม frontend framework

## การติดตั้งและ Migration

`setupTncMemberSystem()` ต้อง:

1. ต่อท้ายคอลัมน์ใหม่ใน `Members`
2. สร้าง `Orders` หากยังไม่มี
3. เพิ่ม `LAST_ORDER_SEQUENCE` หากยังไม่มี
4. ตั้ง header, frozen row และรูปแบบคอลัมน์
5. ตั้ง schema version ใหม่
6. เติมสมาชิกเดิมเป็น `0` แต้ม, `Silver`, `lastOrderAt` ว่าง

เพิ่มฟังก์ชันติดตั้ง time-driven trigger รายคืน โดยต้องมี trigger ประเภทนี้เพียงหนึ่งรายการ
เพื่อไม่ให้ทำงานซ้ำ Trigger ตรวจเฉพาะความแตกต่างระหว่าง summary ใน Members กับ
Orders และเขียนเมื่อค่าไม่ตรง การอัปเดตปกติยังเกิดทันที ไม่ต้องรอ trigger

## ความถูกต้องและความปลอดภัย

- ใช้ `LockService` กับ mutation ทั้งหมด
- ตรวจ memberId และ orderId ฝั่ง server เสมอ
- ห้ามเชื่อ amount, tier หรือ points ที่ client ส่งมา
- amount ต้องเป็นตัวเลข finite และ normalize เป็นทศนิยม 2 ตำแหน่ง
- ป้องกัน CSV formula injection หากเพิ่ม Orders export ในอนาคต
- ไม่แสดง stack trace หรือรายละเอียด Sheet แก่ผู้ใช้
- AuditLog เก็บ actor ของทุกการสร้างและยกเลิก
- Rebuild ต้องคำนวณจาก Orders ซึ่งเป็น source of truth

## การจัดการข้อผิดพลาด

- validation error คืน field errors ภาษาไทย
- ถ้าหา member/order ไม่พบ คืน `NOT_FOUND`
- ถ้าสมาชิกถูกระงับระหว่างเปิด modal ให้ปฏิเสธการสร้างออร์เดอร์
- ถ้าออร์เดอร์ถูกยกเลิกจากคำขออื่น ให้คืน `ORDER_ALREADY_CANCELLED`
- ถ้าการเขียนล้มเหลว ให้ mutation หยุดและแสดงข้อความลองใหม่ โดย AuditLog
  ต้องไม่อ้างว่าสำเร็จ

Google Sheets ไม่มี database transaction แบบ rollback เต็มรูปแบบ จึงใช้ lock,
ลำดับการเขียนที่กำหนด และ reconciliation รายคืนเป็นชั้นตรวจสอบเพิ่มเติม

## แผนทดสอบ

### Unit

- amount ที่ถูกต้องให้แต้มเท่ากับยอด
- ปฏิเสธยอดศูนย์ ยอดติดลบ NaN และยอดเกินเพดาน
- Tier boundaries: 0, 29,999.99, 30,000, 99,999.99, 100,000
- summary ไม่นับออร์เดอร์ CANCELLED
- benefits ตรงกับแต่ละ Tier

### Service

- สร้างออร์เดอร์ออกเลขต่อเนื่องและอัปเดตแต้ม/Tier ทันที
- คำขอพร้อมกันไม่ออกเลขซ้ำ
- ปฏิเสธ member ที่ไม่มีอยู่หรือถูกระงับ
- ยกเลิกหักแต้ม ลด Tier และบันทึกเหตุผล
- ยกเลิกซ้ำถูกปฏิเสธ
- rebuild ซ่อม points, tier และ lastOrderAt จาก source of truth
- AuditLog ครบโดยไม่รั่วข้อมูล auth

### API และ UI

- ผู้ไม่มีสิทธิ์เรียก admin API ไม่ได้
- session สมาชิกเห็นเฉพาะออร์เดอร์ของตน
- ตารางแบ่งหน้าและแสดง ACTIVE/CANCELLED ถูกต้อง
- loading, duplicate click, error และ retry ทำงาน
- ไม่มีการแทรกข้อมูลผู้ใช้ผ่าน `innerHTML`
- desktop, mobile, keyboard และ screen reader ใช้งานได้

## เกณฑ์สำเร็จ

- แอดมินสร้างและยกเลิกออร์เดอร์จากหน้าหลังบ้านได้
- แต้มและ Tier เปลี่ยนทันทีและตรงกับออร์เดอร์ ACTIVE
- สมาชิกเห็นแต้ม สิทธิประโยชน์ และประวัติของตนหลังล็อกอิน
- การยกเลิกเก็บประวัติครบและลด Tier เมื่อยอดต่ำกว่าเกณฑ์
- ระบบเดิม สมัครสมาชิก ล็อกอิน แก้ข้อมูล ระงับ และ PIN ยังทำงานครบ
- ชุดทดสอบทั้งหมดผ่านและ deployment migration ไม่ทำข้อมูลสมาชิกเดิมหาย
