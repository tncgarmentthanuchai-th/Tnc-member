# Member Profile Edit Design

## Goal

ปรับส่วนข้อมูลส่วนตัวหลังสมาชิกล็อกอินให้ดูง่าย แก้ไขข้อมูลได้อย่างชัดเจน และบันทึกลง Google Sheets เฉพาะเมื่อสมาชิกกดปุ่มยืนยัน

## Scope

สมาชิกแก้ไขข้อมูลทั่วไปได้เฉพาะ:

- ชื่อ-นามสกุล
- ประเภทองค์กร
- ชื่อองค์กร

การเปลี่ยนเบอร์โทรศัพท์เป็นขั้นตอนแยกและต้องยืนยันด้วย PIN ปัจจุบัน

## User Interface

### Profile summary

ส่วน `ข้อมูลส่วนตัว` เริ่มต้นในโหมดอ่านอย่างเดียว โดยแสดงข้อมูลสมาชิกปัจจุบันและปุ่ม `แก้ไข`

เมื่อกด `แก้ไข`:

- ซ่อนค่าที่แสดงแบบอ่านอย่างเดียว
- แสดงช่องชื่อ-นามสกุล ประเภทองค์กร และชื่อองค์กร
- แสดงปุ่ม `บันทึกข้อมูล` และ `ยกเลิก`
- ไม่แสดงช่องเบอร์โทรหรือ PIN ในฟอร์มนี้

เมื่อกด `ยกเลิก` ระบบคืนค่าในช่องกรอกเป็นข้อมูลล่าสุดจาก server และกลับสู่โหมดอ่านอย่างเดียวโดยไม่ส่งคำขออัปเดต

### Phone change

เบอร์โทรศัพท์แสดงในส่วนแยกพร้อมปุ่ม `เปลี่ยนเบอร์โทร`

เมื่อกดปุ่ม ระบบแสดงฟอร์ม:

- เบอร์โทรใหม่
- PIN ปัจจุบัน
- ปุ่ม `ยืนยันเปลี่ยนเบอร์`
- ปุ่ม `ยกเลิก`

ระบบไม่เปลี่ยนเบอร์จนกว่าสมาชิกจะกดยืนยัน

## Data Flow

### General profile update

Client เรียก `updateMemberAccount(payload)` พร้อม session token และข้อมูลทั่วไป โดยส่งเบอร์โทรปัจจุบันจาก state ภายในแทนการเปิดให้แก้ในฟอร์มทั่วไป

Server:

1. ตรวจ session สมาชิก
2. ตรวจรูปแบบข้อมูล
3. ยืนยันว่าเบอร์โทรไม่ได้เปลี่ยนผ่าน operation นี้
4. อัปเดต `Members`
5. บันทึก `MEMBER_UPDATE` ใน `AuditLog`
6. คืนข้อมูลสมาชิกเวอร์ชันล่าสุด

Client แสดงข้อความสำเร็จ อัปเดต summary และออกจากโหมดแก้ไข

### Phone update

Client เรียก `updateMemberAccount(payload)` ด้วยเบอร์ใหม่และ PIN ปัจจุบัน

Server:

1. normalize เบอร์เดิมและเบอร์ใหม่
2. ตรวจ PIN ปัจจุบัน
3. ตรวจเบอร์ซ้ำด้วย normalized phone
4. อัปเดตเบอร์และเพิ่ม `sessionVersion`
5. บันทึก audit

เมื่อสำเร็จ Client ล้าง session ปัจจุบัน ออกจากระบบ และแจ้งให้ล็อกอินด้วยเบอร์ใหม่ ทุก session เดิมจะใช้ต่อไม่ได้

## Validation And Errors

- ชื่อ-นามสกุลและชื่อองค์กรต้องไม่ว่างและไม่เกินขนาดเดิมของระบบ
- ประเภทองค์กรต้องเป็นค่าที่ระบบรองรับ
- เบอร์ใหม่ต้องเป็นเบอร์ไทยที่ valid หลัง normalize
- เบอร์ซ้ำแสดงข้อความเฉพาะเจาะจง
- PIN ผิดแสดงข้อความเฉพาะเจาะจง
- ระหว่างบันทึก disable ปุ่มเพื่อป้องกันการกดซ้ำ
- หาก server ล้มเหลว ให้คงข้อมูลในช่องกรอกไว้เพื่อแก้ไขและลองใหม่
- ข้อความสำเร็จและผิดพลาดใช้ live region ที่อ่านได้ด้วย screen reader

## Security

- ทุก operation ตรวจ session ฝั่ง server
- การแก้ไขข้อมูลทั่วไปไม่ต้องส่ง PIN
- การเปลี่ยนเบอร์ต้องตรวจ PIN ปัจจุบัน
- เปลี่ยนเบอร์แล้วเพิ่ม `sessionVersion` เพื่อยกเลิกทุก session
- ไม่ส่ง `pinHash`, `pinSalt` หรือข้อมูล authentication กลับ client
- ไม่ใช้ `innerHTML` กับข้อมูลสมาชิก

## Testing

- Profile summary แสดงข้อมูลล่าสุดและเริ่มในโหมดอ่านอย่างเดียว
- Edit/Cancel สลับโหมดและคืนค่าโดยไม่เรียก server
- Save ส่งเฉพาะข้อมูลทั่วไปและเบอร์ปัจจุบัน
- Save สำเร็จอัปเดต summary และ Google Sheet
- Validation หรือ server error คงฟอร์มและข้อมูลที่กรอกไว้
- Phone form แยกจาก profile form
- เปลี่ยนเบอร์ต้องมี PIN และปฏิเสธเบอร์ซ้ำ
- เปลี่ยนเบอร์สำเร็จทำให้ session เดิมใช้ไม่ได้
- ปุ่ม loading, keyboard navigation, mobile layout และ live regions ทำงานถูกต้อง
